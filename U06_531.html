Database Structures

Explore how data is organized, from the rigid architecture of structured tables to the flexible expanses of non-structured documents.

Data Structures

  • Structured Data: Organized logically, easy to read, and adheres to a predefined schema.
  • Semi-Structured Data: Does not conform to a rigid schema but uses tags and metadata for some organization.
  • Non-Structured Data: Lacks predefined structure, often complex multimedia, making it challenging to process.

Relational Databases

  • Tables & Records: Stores data in a structured format utilizing rows (records) and columns (fields).
  • Primary Keys (PK): Fields that uniquely identify each independent record within a table.
  • Foreign Keys (FK): Fields that establish crucial relationships or links across different tables.

Schema & Data Models

  • Schema Rules: The foundational rules that define data organization and enforce data integrity constraints.
  • Logical Data Models: Outline the database structure abstractly, identifying tables, relationships, and constraints.
  • Physical Data Models: The exact code and syntax required to create the database in a specific DBMS (like SQLite).

Non-Relational Databases

  • NoSQL Flexibility: Provides various ways to store and manage data lacking rigid predefined structure.
  • Key-Value Stores: Utilizes a unique key identifier to rapidly retrieve associated data values without a schema.
  • Document Databases: Stores independent units of data (documents) which often include nested files or arrays.
